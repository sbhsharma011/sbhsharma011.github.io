StockAnalystAgent

Multi-agent AI system for real-time stock analysis and trading recommendations

View on GitHub ↗

The Problem

Retail investors are flooded with market data but starved for synthesis. A single ticker check involves cross-referencing live price, daily volume, percentage change, and momentum — then translating those signals into an actual decision. Most free tools stop at showing the numbers; they don't reason about what the numbers mean or commit to a recommendation. That gap forces investors to either do the analysis manually or rely on paid terminals built for professionals, not everyday users.

The Solution

StockAnalystAgent closes that gap with a two-agent AI pipeline: one agent pulls and interprets live market data, a second agent evaluates that analysis and produces a clear Buy, Sell, or Hold recommendation with reasoning — delivered through a conversational chat interface where a user just types a ticker symbol.

How It Works

The system is built on CrewAI, an orchestration framework for coordinating multiple specialized LLM agents toward a shared goal:

  1. Stock Analyst Agent — queries live market data (current price, daily change, volume) via the Yahoo Finance API and produces a structured summary of the stock's current performance and any notable trends.
  2. Stock Trader Agent — takes that summary and reasons over it like a trading strategist: assessing momentum and risk, then issuing a confident Buy/Sell/Hold call with supporting justification and, where relevant, a suggested holding window.

The two agents run sequentially in a Crew, each with a distinct role, goal, and backstory that shapes how it reasons — the analyst stays descriptive and data-driven, the trader is the one that commits to a decision. This separation keeps each agent's prompt focused and makes the reasoning at each step auditable, rather than asking one model to do data lookup and financial judgment in a single pass.

Tech Stack

  • CrewAI — multi-agent orchestration
  • Groq (LLaMA 3.3 70B) — low-latency LLM inference for both agents
  • yfinance — live market data
  • Streamlit — chat-based front end

Key Design Decisions

  • Separation of concerns between agents — splitting "what happened" from "what to do about it" produces more consistent, well-justified recommendations than a single monolithic prompt, and makes it straightforward to swap or improve one agent's behavior without touching the other.
  • Groq for inference — chosen for response speed, since the app is conversational and users are waiting on a live chat reply, not a batch report.
  • Environment-based configuration — API keys are never hardcoded; the app loads credentials from environment variables so it's safe to run locally or deploy without exposing secrets.
